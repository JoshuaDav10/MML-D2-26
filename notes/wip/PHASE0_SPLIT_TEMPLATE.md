# Phase 0 Split Template

**Status:** PROVEN — build is byte-identical after split of func_8002F9C4.
**Date:** 2026-07-26

## What this is

This documents the exact procedure for splitting a raw-asm function out of one
of the giant monolithic `.s` files (asm/rock_neo/{10638,32A38,4C710,52C0,543A8,77D4}.s)
into a per-function INCLUDE_ASM C stub, while keeping the binary byte-identical.

Guinea pig: **func_8002F9C4** (file offset 0x1F9C4, VMA 0x8002F9C4, 10 instructions / 0x28 bytes,
lived in asm/rock_neo/10638.s which originally covered offsets 0x10638–0x2C640).

## Background: what git tracks vs what's local

The repo tracks:
- `src/rock_neo/*.c` — C stubs with INCLUDE_ASM calls
- `config/splat.us.rock_neo.yaml` — segment map
- `asm/rock_neo/nonmatchings/**/*.s` — individual function asm files (per-function)

The repo does NOT track (gitignored, local/generated):
- `asm/rock_neo/*.s` — giant monolithic asm blocks (generated by splat, maintained manually)
- `rock_neo.ld` — linker script (generated by splat, maintained manually)

## The three-part relationship for mapped functions

1. **yaml entry** `[0x1F9C4, c, Code8002F9C4]` — tells splat: "there's a C segment at this file offset"
2. **nonmatchings .s** `asm/rock_neo/nonmatchings/Code8002F9C4/func_8002F9C4.s` — the function asm
3. **C stub** `src/rock_neo/Code8002F9C4.c` — calls `INCLUDE_ASM(...)` which inline-includes the .s

## Exact reproducible procedure

### 1. Identify the target function

```bash
grep -l "glabel func_XXXXXXXX" asm/rock_neo/*.s   # find which giant .s file
grep -n "nonmatching func_XXXXXXXX" asm/rock_neo/NNNNNN.s  # get line numbers
```

The `nonmatching` directive is always one line before `glabel`, includes size in hex.
Example: `nonmatching func_8002F9C4, 0x28` means 0x28 bytes (10 instructions).

### 2. Calculate file offsets

```python
# VMA to file offset:
file_offset = vma - 0x80010000   # base vram = 0x80010000
func_offset = 0x8002F9C4 - 0x80010000  # = 0x1F9C4
end_offset = func_offset + func_size    # = 0x1F9EC
```

### 3. Create the nonmatchings .s file

Create `asm/rock_neo/nonmatchings/Code8002XXXX/func_8002XXXX.s`:

```asm
.set noat      /* allow manual use of $at */
.set noreorder /* don't insert nops after branches */

nonmatching func_8002XXXX, 0xSIZE

glabel func_8002XXXX
    /* ... all instructions verbatim from the giant .s ... */
```

Copy the `nonmatching` directive + `glabel` + all instruction lines exactly from the giant .s.

### 4. Create the C stub

Create `src/rock_neo/Code8002XXXX.c`:

```c
#include "common.h"

INCLUDE_ASM("config/../asm/rock_neo/nonmatchings/Code8002XXXX", func_8002XXXX);
```

The INCLUDE_ASM path must be relative to the build root (starts with `config/../`).

### 5. Edit the yaml (config/splat.us.rock_neo.yaml)

Replace the single asm entry that contains the function:

```yaml
# Before:
- [0xNNNNN, asm]

# After (split into three):
- [0xNNNNN, asm]           # splits to NNNNN.s (everything before the function)
- [0xFUNC_OFFSET, c, Code8002XXXX]   # the function itself
- [0xEND_OFFSET, asm]      # splits to ENDOFFSET.s (everything after)
```

File offsets are in hex without leading `0x`, uppercase. The asm segment names must
match the file offset (e.g. offset 0x1F9EC → file `1F9EC.s`).

### 6. Edit the local rock_neo.ld

Replace the single `.s.o` line with three lines:

```
# Before:
build/asm/rock_neo/NNNNN.s.o(.text);

# After:
build/asm/rock_neo/NNNNN.s.o(.text);
build/src/rock_neo/Code8002XXXX.c.o(.text);
build/asm/rock_neo/ENDOFFSET.s.o(.text);
```

### 7. Split the local giant .s file

This is the most critical step. You must split the giant .s into TWO files.

**Part A** (`asm/rock_neo/NNNNN.s`) — keep all content up to (and including) the last
instruction of the function BEFORE the target function:

```python
lines = open('asm/rock_neo/NNNNN.s').readlines()
# Find the line of the blank line before "nonmatching func_TARGET" and truncate there.
# The last line should be the last instruction of the preceding function.
lines = lines[:LAST_LINE_BEFORE_TARGET]
open('asm/rock_neo/NNNNN.s', 'w').writelines(lines)
```

**Part B** (`asm/rock_neo/ENDOFFSET.s`) — new file starting from the function AFTER
the target:

```python
# Create the post file with proper header + all content from next function onward
with open('asm/rock_neo/ENDOFFSET.s', 'w') as f:
    f.write('.include "macro.inc"\n\n.set noat\n.set noreorder\n\n')
    # append from "nonmatching func_NEXT_FUNC" onward
    lines = open('asm/rock_neo/NNNNN.s_backup').readlines()
    f.writelines(lines[FIRST_LINE_OF_NEXT_FUNC:])
```

**CRITICAL:** Do NOT leave the target function's instructions in NNNNN.s. 
Do NOT leave the post-function content in NNNNN.s. Both mistakes cause duplicate
bytes in the output (either a larger binary or linker relocation errors).

### 8. Force rebuild and verify

```bash
rm -f build/asm/rock_neo/NNNNN.s.o build/asm/rock_neo/ENDOFFSET.s.o build/rock_neo.elf
touch src/rock_neo/*.c
make CPP=cpp check_rock_neo_only   # must print OK
```

## Mistakes made and lessons

1. **First attempt:** Created `10638_pre.s` and `10638_post.s` but forgot to truncate
   `10638.s` — it still had ALL content including the post-function range. The linker
   got duplicate `.text` content causing GP-relative relocation truncation errors in
   unrelated C files (scene.c). The error manifested as "relocation truncated to fit:
   R_MIPS_GPREL16" — a misleading symptom that points to layout shifts, not the actual cause.

2. **Naming:** Splat names asm files by their file offset in uppercase hex without `0x`
   prefix (e.g. `1F9EC.s` for offset 0x1F9EC). Use these names for the split files.

## Batch scaling

For the ~635 remaining raw functions across 6 giant .s files, the same pattern applies
to each. The key mechanical steps per function are:
1. Find function's `nonmatching` block in the giant .s
2. Compute file offset from VMA (subtract 0x80010000)
3. Create nonmatchings .s (copy verbatim)
4. Create C stub (3 lines)
5. Edit yaml (split one `asm` entry into three)
6. Edit rock_neo.ld (split one `.s.o` reference into three)
7. Trim the giant .s and create the new post-.s file

Each split shifts the boundary of the preceding asm segment. For batch work,
process functions in ascending address order within each giant .s file so each
successive split only needs to adjust the preceding segment's end.
